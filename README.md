# S.P.L.U.R.T. Station Atlas

**Live map: [scolastico.github.io/splurt-atlas](https://scolastico.github.io/splurt-atlas/)**

A static, zoomable map of [S.P.L.U.R.T.](https://github.com/SPLURT-Station/S.P.L.U.R.T-tg) stations. Node.js scripts acquire a pinned source checkout, parse BYOND DMM/TGM maps and DM declarations, decode DMI sprite sheets, and bake browser-ready WebP tiles. The deployed app needs no server, database, BYOND installation or API key.

## Run locally

Requires Node.js 22+ (24 recommended), pnpm 10.28 and Git. From this directory:

```powershell
pnpm install
pnpm source
pnpm export
pnpm dev
```

Open the local URL printed by Vite (normally http://127.0.0.1:5173). This delivered folder already has its own source checkout and exported station data, so `pnpm dev` is sufficient to start exploring. `pnpm build` produces the ready-to-host `dist/` folder; `pnpm preview` serves that build locally. Serve over HTTP, rather than opening `index.html` with `file://`, because the viewer fetches map data and runs a worker.

Development serves exported files on demand and excludes generated maps, old snapshots, source checkouts and scratch folders from Vite's watcher. It saves generator-file hashes, the locally checked-out upstream commit and the completed catalog identity in `.cache/dev-generation-stamp.json`. Unchanged restarts and UI-only edits reuse that export. Missing data, generator changes or a different local upstream commit automatically start incremental generation, fetching the pinned source first if no checkout exists. Unchanged map assets and ZIPs are reused. Edits during generation cancel the stale process; after a short debounce, generation restarts using the latest inputs. Only a complete, still-current staging snapshot is published.

Conversion uses separate Node worker processes, balancing station batches by their previous exported size. The default is up to four workers, capped by CPU availability and a 2 GiB RAM budget per worker. Set `ATLAS_WORKERS` to a positive integer to override the default (up to eight, still capped by available resources), or set it to `1` for serial conversion. Each worker limits native image processing to one thread to avoid excessive competing threads. Completed maps are checkpointed during conversion; restarting an interrupted generation with the same generator hashes and upstream commit reuses those maps instead of rendering them again. The progress page combines the workers' progress. This also applies to the regular exporter and CI.

A development-only loading page shows validation/export progress and opens the viewer automatically when ready, preserving the URL fragment. Errors stop automatic retries until an input changes or you click **Retry preparation**. Missing data requests return JSON errors instead of falling back to the viewer HTML. The development exporter follows the existing local checkout without changing `atlas.config.json`; production builds still require its configured pin. These development routes and progress scripts are excluded from production builds. You can also run `pnpm prepare:data` or `pnpm package:maps` explicitly.

To seed a fresh project from an existing checkout, without modifying it:

```powershell
pnpm source --from ../S.P.L.U.R.T-tg
```

The project owns its checkout under `.source/S.P.L.U.R.T-tg/`. A local clone reuses Git objects with hard links when available; working files are independent. To retrieve everything from GitHub instead, omit `--from`. The initial source acquisition can be large; the game includes extensive art and audio. `.source`, dependencies, generated maps and build output are ignored by Git.

## Explore

- Opening the page without a map fragment shows a station picker. All **16 station configurations** are available, covering Tramstation, NorthStar, Ice Box, Blueshift, Moon Station and the other configured stations. Minimal Runtime Station, Runtime Station, MultiZ Debug and Gateway Test are excluded in `excludeMaps`. Deck numbers are source-local DMM Z coordinates, not live server Z assignments.
- Drag to pan; scroll, pinch, double-click or use **+ / −** to zoom. **F** fits the station. Arrow keys pan. **/** focuses search. **Escape** closes the inspector.
- **Look through decks** reveals lower levels through space, open-space, glass floors, catwalks and transparent sprite edges. Surfaces compose from bottom to top, so an intervening opaque deck blocks deeper decks. Glass has partial visibility. Ordinary air above an opaque floor does not create a hole.
- The sidebar has **Map & layers**, **Search**, and **Selected tile** tabs. Collapse it with the arrow or drag its right edge to resize it; the width is remembered on this device. Double-click the resize grip to reset the width. Zoom/fit controls float at the bottom right, and deck controls at the top right.
- The tile inspector defaults to readable descriptions: the room and surface, objects present, possible random finds, deck connections, and normal door-access roles. **Detailed view**, off by default, exposes type paths, overrides and source links. Every door shows both who can open it and who cannot, using normal starting IDs. Friendly view combines doors whose normal and expanded access match. Detailed view includes raw requirements, inherited declaration files, mapped helper implementations, and the job ID definitions used to calculate access. Buttons and timers with matching mapped control IDs link directly to their tiles. Following a control link also highlights that specific button at its drawn sprite bounds. Selected-tile toggles can highlight other wall-mounted or offset objects with a pulsing outline and a line back to their mapped tile; selections are restored through the compact `h` parameter. Door access uses starting job ID trims and mapped access helpers; expanded department access is listed separately. Remotely controlled doors and unresolved dynamic rules are labeled instead of being called public.
- **Animated parallax** projects lower decks at increasing distances from the camera, so they recede and move independently when panning. Three star fields drift continuously at different speeds over a moving nebula on a separate background canvas. The motion toggle pauses the animation and removes depth perspective. Reduced-motion preferences disable it by default; animation pauses in hidden tabs.
- Independently toggle **atmospherics**, **power**, **fluid ducts**, **waste disposal**, and **transit tubes**. Exposed pipes, cables, ducts and disposal equipment remain visible with their toggles off; enabling a network additionally reveals components hidden beneath intact flooring. Plating, glass and catwalk visibility follow the mapped turf settings. Transit tubes are **on by default**. Their runtime decorative overlays are reconstructed from the source direction tables, including diagonal pieces shifted into neighboring cardinal tiles. Utility layers show only on the viewed deck. Cables and smart pipes use connecting sprites derived from their mapped neighbors, layers and blocked directions. Nested mapping helpers preserve atmos colors and above-floor variants; connections respect color compatibility, all-color adapters and piping layers. Rotated filter ports and their connected underlays are reconstructed. Bridge pipes use their correct axis and raised center; layer adaptors show the connected layer branches on each side. Fluid ducts retain assigned colors and layer offsets. Disposal pipe layers render beneath other pipes and wiring. Equipment is rendered after utility layers so canisters and flow meters stay above connectors and pipes. **Simple utility symbols** replaces power cables and atmospheric pipe segments with lightweight crosses; exposed equipment keeps its game sprites.
- **Color separate power networks** gives each connected cable component a distinct color. The graph accounts for cable layers, blocked links, multi-Z hubs and the normal SMES input/output separation. This describes mapped wired connectivity, not whether a network is energized during a round.
- **Door access** uses a tag input with Fuse.js fuzzy autocomplete to combine crew roles. Green means every selected role can enter with normal starting access; yellow means only some can enter, or expanded access is required; red means none can enter even with expanded access. Remote doors are red and unknown dynamic access stays unmarked. Markers pulse only on the viewed deck. Selected roles are restored from the compact `j` URL parameter.
- **Highlight stairs & ladders** marks mapped deck connections with gently pulsing circles (static with reduced motion); **Show where stairs & ladders lead** adds an arrow in the center of each tile: up, down, or both directions. Arrows and highlights appear only on the viewed deck. Destination decks and rooms remain in the tile inspector; unresolved destinations have no direction arrow.
- Reflectors use their real base and mirror/box overlays, rotated to their mapped angle rather than showing mapper arrows.
- **Replace runtime-generated turfs** is on by default. Bright green/blue/orange mapper placeholders are replaced visually with the area's representative terrain: snow/ice on Ice Box and appropriate lunar or volcanic ground on Moon Station. Deterministic sprite variants blend with the surrounding terrain. Turn it off to inspect the original placeholders. This is a terrain preview, not a reconstruction of a particular round's procedural seed; mapped objects, room metadata and original turf types are preserved.
- **Room boundaries** adds stable region colors, boundaries, and room labels when zoomed in. Click a tile for the area path, region, turf, placed objects, variable overrides, and links to the pinned game source. Opaque pixels cover lower decks; transparent sprite edges preserve visibility rather than cutting a whole tile out of the view.
- Search room names, item names or full DM paths across all decks. Bundled **Fuse.js** performs fuzzy search offline in a worker, tolerating misspellings such as `wernch`. **Placed** means a directly mapped `/obj/item`; **Possible** means a statically discoverable loot-table candidate. Results group the same item and spawn classification together, deduplicating coordinates across spawners. Selecting a result uses the normal tile inspector, briefly pulses the selected tile, and lists every distinct finding by room, deck and coordinates. The list has 30 locations per page, with every page accessible; matching tiles pulse continuously on the current deck, using a separate overlay so the station canvas remains idle. Reduced-motion preferences keep the markers static. The result list shows the first 70 ranked groups and reports the total.
- The compact URL fragment stores the station (`m`), deck (`z`), camera (`x`,`y`), zoom (`s`), selected tile (`t=X,Y,Z`), query (`q`), grouped result (`r`) one-based finding number (`f`), and selected door-highlight roles (`j`). Sidebar toggles, including search filters, detailed view, are packed into the decimal bitmask `o`. Links restore the same options and selection. Only these compact keys are supported; the earlier unpublished long-key format was removed. On portrait phones the explorer becomes a resizable bottom panel, leaving the map above it. Interface font sizes use `rem` and follow the browser?s base text setting, with larger sidebar labels and descriptions. Desktop and portrait panels animate together with the map centering offset, preserving the full-size canvas and respecting reduced-motion preferences. Sidebar width, bottom-panel height, collapse preference and offline storage mode are stored on the device. Offline storage never travels in a shared URL.
- On the first visit, choose **Download all maps** (recommended), **Current map only**, or **No offline storage**. The chooser and sidebar show disk-size estimates for all maps and the current map, plus the smallest to largest map range when switching stations. The choice stays in localStorage, outside the URL. All-map mode saves metadata, search data and every sprite/zoom image in IndexedDB, including unopened maps. Current-map mode fully saves one station and removes the previous station when switching; outdated export revisions are removed too. No-storage mode bypasses and clears this app's IndexedDB map data (ordinary HTTP caching is browser-managed). Progress confirms when the download is saved. Reopening checks the small catalog and reuses saved resources. Unavailable/full storage is reported. The app shell remains ordinary static HTML/JavaScript.

Offline saving downloads one ZIP per map instead of hundreds of separate files. Maps without a packaged ZIP are never fetched file by file. ZIPs are first saved in the IndexedDB `archives` store, then JSZip extracts bounded batches in a background worker into the normal `assets` store. Reopening reuses complete assets without downloading again; interrupted extraction resumes from its saved ZIP. Changing maps in current-map mode, changing revisions, or disabling storage prunes both stores. Existing complete caches are retained without downloading ZIPs again. The chooser and sidebar show separate **Download size** (ZIP transfers) and **Extracted size** (final saved assets), including per-map ranges. Each ZIP is deleted once all extracted asset transactions commit; interrupted extractions retain their ZIP for retry. Temporary space is needed for one archive during extraction. An indicator beside the zoom controls stays visible while any requested map is caching. Once the current map is complete, it reports that the map is ready while others are still being prepared. Downloads wait until a map is selected. Its ZIP is downloaded and fully extracted before any other ZIP starts; switching maps moves the new selection to the front of the remaining queue. Visible chunks plus current-deck metadata are extracted first; foreground map requests have higher priority than background ZIP transfers. ZIP links appear only in the sidebar for the current station, and work independently of offline storage.

`pnpm build` packages all maps automatically before building the static site. `pnpm package:maps` refreshes ZIPs separately, using the current exported snapshot. Archives contain the map's `assets.json` inventory, metadata, search data and all sprites/zoom levels, with paths relative to that map. Identical map versions retain their archives; ZIP timestamps are fixed so regenerated archives have stable checksums. ZIPs are included in the release branch.

The `o` bitmask uses these bit positions (a set bit enables the option):

| Bit | Option | Bit | Option |
| --- | --- | --- | --- |
| 0 | Atmospherics | 8 | Simple utility symbols |
| 1 | Power cables | 9 | Stair/ladder highlights |
| 2 | Waste disposal | 10 | Stair/ladder direction arrows |
| 3 | Transit tubes | 11 | Detailed tile inspector |
| 4 | Room boundaries | 12 | Placed items in search |
| 5 | Lower-deck visibility | 13 | Possible items in search |
| 6 | Animated parallax | 14 | Runtime terrain replacement |
| 7 | Separate power-network colors | 15 | Fluid ducts |

For example, bit 3 has value `8`; combining enabled options adds their values. A complete shared link might start with `#m=tramstation&z=2&x=3632&y=6160&s=1&o=29800`.

## Export another station or revision

Edit `atlas.config.json`. `ref` is an exact upstream Git commit, `maps` contains station JSON basenames from upstream `_maps/`, `chunkTiles` is the baked image grid size, and `tilePixels` is 32 for this game. Keep `tilePixels` at 32; the viewer's coordinate and aperture renderer uses BYOND's native 32-pixel tiles.

```powershell
pnpm source
pnpm export
pnpm test
pnpm build
```

The default `"maps": "all"` exports all upstream station configurations except the IDs in `excludeMaps`. Use an array of configuration basenames for a smaller catalog, or `pnpm export tramstation` for one map. `pnpm export --all` also respects exclusions. Exports are prepared in `.cache/` and published only after conversion succeeds. A failed conversion leaves the previous working export in place; discard leftover `.cache/export-*` folders when convenient. Run one exporter at a time. `pnpm build` rejects missing data and an export whose commit does not match the configured pin. It never downloads or converts the upstream source implicitly.

On Windows, preview file watchers can lock `public/data/` against a directory swap. In that case the exporter publishes an immutable snapshot inside `public/data/snapshots/` and atomically switches the root manifest to it. Existing views keep their old data until reloaded. The production build copies only the currently selected dataset, so old snapshots never inflate the deployed site. Failed conversions leave the previous manifest intact. A completed staging directory can also be published with `node scripts/promote.mjs .cache/export-<uuid>` without repeating conversion.

## GitHub Pages

1. Create a repository containing this project, including `pnpm-lock.yaml`, `atlas.config.json` and `.github/workflows/pages.yml`. Do not commit `.source/` or `public/data/`.
2. In repository **Settings → Pages**, select **Deploy from a branch**, then choose **release** and **/ (root)** after the first successful workflow creates that branch.
3. Push to `main`, or run **Build station atlas and publish release branch** manually. Pull requests build and retain a review artifact without deploying.

The workflow resolves the latest upstream default-branch commit, pins that exact SHA for the run, installs the locked dependencies, downloads/caches that upstream checkout, runs parser tests, converts station data, builds `dist`, checks a conservative 950 MiB site budget, and publishes the generated files plus `.nojekyll` to the `release` branch. Every publication force-replaces that branch with one orphan commit containing only the current site, keeping old generated snapshots out of its reachable history. The source branch history is preserved. GitHub may retain unreachable objects and old workflow artifacts until its own cleanup runs. It never enables Pages or changes the configured publishing source. Once branch publishing is enabled, the workflow requests a Pages refresh because GitHub does not automatically build Pages for commits pushed with `GITHUB_TOKEN`. It uses relative asset URLs, so repository paths such as `/station-atlas/` work without changing a base URL. Hash navigation needs no server rewrite rules. The workflow sets `VITE_ATLAS_SOURCE_URL` to the atlas repository so visitors can find the application source. Set that environment variable yourself for other hosting providers.

The workflow checks upstream on the first of each month at **04:23 UTC**, comparing upstream HEAD with the catalog committed to `release`. It skips the build when the revisions match. Pushes and manual runs also rebuild the web application, while reusing converted map data where possible. Under **Actions -> Build station atlas and publish release branch -> Run workflow**, enable **full_rebuild** to explicitly reconvert every map. The runner remains the standard `ubuntu-latest` machine; no paid runner is configured.

Incremental runs restore `release/data`, compare upstream Git files since that catalog's commit, and reuse maps with no relevant changes. When DM code changes, the exporter checks resolved types (including inheritance), map metadata, search candidates, utilities, natural terrain, smoothed appearances and icon file hashes before rendering. Only maps with different rendering inputs are converted. Shared code, icons or converter changes can legitimately affect many maps. Missing or incomplete output is rebuilt. Each reused map retains its browser-cache version; an update to one map does not invalidate every station's IndexedDB images. `data/build-report.json` and the Actions summary list changed files, rebuilt maps and reused maps. On the first migration, a completed trusted main-branch build artifact can be adopted at the same upstream revision after metadata verification, even if its old Pages deployment failed. A missing baseline falls back to a full export.

For local incremental exports, put the previous static dataset in `.cache/baseline/data` (or set `ATLAS_BASELINE` to its data directory), then run `pnpm export --incremental`. Use `pnpm export --full` for a clean reconversion. Set optional `upstreamRef` in `atlas.config.json` to track a particular full branch ref instead of upstream HEAD. CI changes the source pin only inside its runner; local conversion uses the checked-in `ref`. Scheduled workflows must be enabled on the default branch; GitHub may disable schedules in inactive public repositories after 60 days ([GitHub schedule documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)).

The project repository is [scolastico/splurt-atlas](https://github.com/scolastico/splurt-atlas). Enable GitHub Pages from the `release` branch root in repository settings when ready to deploy. Conversion runs in CI; GitHub Pages only serves the resulting files.

## Pipeline and output format

| Location | Purpose |
| --- | --- |
| `scripts/source.mjs` | Download or locally clone upstream and check out the exact configured commit |
| `scripts/lib/dmm.mjs` | Parse dictionaries, overrides, strings, nested lists, and coordinate blocks |
| `scripts/lib/dm.mjs` | Read declarations in `.dme` include order, inherit properties and static loot pools |
| `scripts/lib/appearance.mjs` | Expand declarative structure spawners and ordinary neighbor bitmask smoothing |
| `scripts/lib/dmi.mjs` | Read PNG DMI metadata; extract the first animation frame in the mapped direction |
| `scripts/export.mjs` | Bake sparse chunk strips, their level-of-detail pyramid, overview strips, previews, transparency metadata, rooms and search records |
| `scripts/lib/map-format.mjs` | Schema 3 encoder/decoder: shared atom/string/value tables, run-length grids, search point sets and strip channel masks |
| `scripts/lib/image-pyramid.mjs` | Write chunk strips and build the 2×2 level-of-detail pyramid from them |
| `scripts/lib/infrastructure.mjs` | Derive cable components, connecting cable/pipe states, and deck destinations |
| `scripts/lib/door-access.mjs` | Resolve mapped door requirements against normal and expanded job ID access |
| `scripts/index-assets.mjs` | Write full offline asset inventories and assign a new cache build ID |
| `public/data/manifest.json` | Schema version, source repository/commit, station catalog and tile dimensions |
| `public/data/<map>/map.json` | Areas, room anchors, source paths, map traits, door roles and infrastructure graphs; definitions reference a deduplicated atom table whose strings and access rules are interned |
| `public/data/<map>/assets.json` | Relative paths and byte sizes for pre-caching the complete map |
| `public/data/<map>/<z>.json` | Run-length encoded north-up row-major tile dictionary indices (`-1` for unmapped cells), station bounds, chunk list with channel bitmasks |
| `public/data/<map>/<z>/` | One lossless WebP strip per chunk (`c-<x>-<y>.webp`) stacking every present channel, level-of-detail strips `l1-<x>-<y>.webp` (32 × 32 tiles) and `l2-<x>-<y>.webp` (64 × 64 tiles) at the same 512 px size, terrain and utility overview strips, coarse PNG aperture mask |
| `public/data/<map>/preview.webp` | Small station preview for the picker (`preview-natural.webp` with generated terrain) |
| `public/data/<map>/search.json` | Item records, placed/possible classification, candidate spawner, and flat XYZ triples; identical point lists are stored once |
| `public/data/<map>/report.json` | Unresolved spawners and sprite fallback counts/samples |
| `public/data/asset-sources.json` | Referenced DMI paths and the exact source revision |

Map coordinates remain BYOND's one-based X/Y/Z; image Y coordinates are flipped so north is up. JSON dictionaries preserve original map object paths and overrides; `decodeMap`, `decodeLevel` and `decodeSearch` in `scripts/lib/map-format.mjs` expand the compact files into plain objects (the viewer and smoke scripts use the same functions). Strip slots follow the fixed channel order `base, foreground, pipes, power, fluid, disposal, transit, disposal-surface, pipes-surface, power-surface, fluid-surface, natural`; a chunk's bitmask says which slots exist, and absent channels occupy no pixels. Compared with the previous per-channel files, a station needs roughly a fifth of the files and well under half of the bytes. A one-cell sprite gutter retains common pixel offsets and oversized sprites across chunk boundaries. Icons larger than the supported 96 × 96 tile composition, or offsets outside that gutter, are omitted. A failed conversion exits nonzero; rerun it before building updated data.

When the root manifest contains `dataPath`, the map paths in this table are relative to that snapshot directory. The production build flattens the selected snapshot back to `dist/data/` and omits `dataPath`.

## Performance

The viewer draws station imagery with WebGL (`src/gl-renderer.js`): every strip becomes a texture, each visible tile is one textured quad per channel, and deck shading happens in the fragment shader, which is mathematically identical to shading a composited deck. A Canvas 2D fallback with intermediate canvases exists for browsers without WebGL. Room boundaries, utility symbols, labels and the selection live on a separate 2D annotation canvas that is cleared only while it has content. The viewer requests only visible chunk strips: one request per visible tile delivers every channel of that tile, so enabling a utility layer never triggers new downloads. Resolution depends solely on zoom: below 12.5% it uses whole-station overview strips, from 12.5% it uses level-2 strips (64 × 64 tiles per 512 px image), from 25% level-1 strips (32 × 32 tiles), and from 50% native chunk strips (16 × 16 tiles). Every level keeps the same pixel size per image, so a viewport needs a similar number of images and draw calls at any zoom. Panning, station boundaries, enabled layers and visible chunk counts never change the selected resolution. Sprite pixels use nearest-neighbor rendering. Images are decoded with `createImageBitmap` off the main thread and uploaded as textures. A tile that is not decoded yet borrows the matching region of its nearest decoded coarser level or of the overview, so only that tile looks soft for a moment instead of the whole deck dropping a resolution. One tile beyond the edges the camera moves toward is prefetched at low priority, and tiles used within the last two seconds are never evicted, so a drag that changes direction does not re-download its own prefetches. The space background is repainted only by its own animation loop or when its inputs change, and the highlight overlay is cleared only while it has content.

The texture cache targets 128 MiB, grows to 1.5× whatever the current frame and its prefetch need, and protects visible images, terrain overview fallbacks and the initial zoom neighborhood even if they exceed that target. The loading animation covers metadata/search preparation and decoding exactly what the first frame draws; the surrounding zoom levels, including the first zoom out, continue loading in the background right after. At most twelve image loads run concurrently, with visible strips queued ahead of warm-up strips. Whole layers switch to a new resolution only when their requested chunks are ready; cached coarser layers remain visible while loading, avoiding transparent gaps and per-image repaint flicker. Background offline downloads use four low-priority requests and yield while a selected station is being prepared. IndexedDB writes are batched with relaxed durability because these files are replaceable cache data.

Metadata uses the compact schema 3 layout: `map.json` shrinks about sevenfold (Tramstation 9.6 MB to 1.3 MB, NorthStar 14.6 MB to 1.8 MB) because the 34,000 mapped atom records collapse into 4,600 shared entries with interned strings, and `search.json` shares identical spawner point lists. The search bytes are transferred to the worker and decoded there. Room boundaries are cached as one fill and one edge path per area and chunk. Fuse.js search and index construction run in a worker with a 130 ms debounce; full coordinates are transferred only for the selected result. Finding lists render 30 rows per page. The station canvas updates on interaction, complete image batches and the short selection pulse. Continuous space motion uses a separate canvas capped at 30 paints per second. Device pixel ratio is capped at two. Encoded resources for all maps live on disk in IndexedDB; only the current station's images are decoded in memory.

These are architectural bounds, not a promise of a particular frame rate on every device. Several transparent decks and room-boundary labeling add work. Export time and memory depend on map complexity; the workflow allows 6 GiB of Node heap and a 60-minute build budget. Broadening the map catalog increases build time and Pages storage use.

## Accuracy and deliberate limits

This is a **static source atlas**, not a BYOND runtime emulator. It includes source maps and discoverable pre-round content. It does not execute Dream Maker, simulate a round, resolve arbitrary preprocessor conditionals, move shuttles into docking ports, generate ruins, or apply procedural map changes.

DM inheritance and simple constant properties are read in source include order. `MAP_SWITCH(runtime, editor)` selects the runtime appearance; simple `TRANSLATE_MATRIX(x,y)` offsets are applied to exported sprites, including oversized asteroid rocks. Ordinary bitmask smoothing uses declared smoothing groups; border-object smoothing, runtime filters, specialized diagonal underlays, lighting, overlays, game sprite animation, procedural icons and arbitrary `Initialize()` changes may differ from the game. Declarative structure `spawn_list` windows and grilles are expanded; procedural variations may remain approximate. Fallback icon states and missing images are counted in export reports. The exporter keeps map facts separately from the rendered approximation.

Possible spawn discovery follows literal `loot = list(...)` paths, nested static spawners and the declared maintenance/dumpster global pools. It does **not** evaluate probabilities, runtime predicates, dynamic subtype pickers, traits, procedural inventory, container population, circuit recipes, random seeds, or every custom spawner. Item locations inside dynamically populated containers are not exhaustive. No probability is claimed; inspect `unresolvedSpawners` for known gaps. Directly mapped random item subtypes may also replace themselves at initialization.

Power components and normal cable/smart-pipe connection sprites are reconstructed from static source rules. Runtime device changes, custom procedural connector rules, gas mixtures, capacity, pressure and actual power flow are not simulated. Stair chains and vertically paired ladders expose mapped destinations; special runtime teleport/ladder links may remain unresolved. Door roles reflect normal starting IDs, not access granted during a round, hacked doors, altered station policies or emergencies. Decks compose using baked sprite alpha, so opaque middle floors block deeper decks and transparent rock edges expose lower content. Glass/catwalk transparency uses known turf families; unusual runtime transparency overrides need explicit exporter rules. Coarse aperture masks remain as metadata. Shared DMM X/Y coordinates provide deck alignment.

## Validation

Run `pnpm audit:offsets` after updating upstream to check inherited and mapped pixel offsets across every exported station. The report at `.cache/offset-audit.json` lists source declarations, unresolved offsets and runtime placement procedures for review. The command fails if a mapped offset cannot be resolved. Named constants, signed/parenthesized values and static `type::property` references are supported; APC and shower map-load placement is shared by the renderer and inspector highlights.

```powershell
pnpm test
pnpm build
node scripts/check-size.mjs
```

Tests cover DMM/TGM coordinates, nested overrides, comments, DMI frame offsets, network classification, cutaway turf rules, deterministic window expansion, wall smoothing, DM inheritance, `MAP_SWITCH` appearance macros, global loot pools, zoom thresholds, fuzzy search, grouped locations and URL state. `pnpm build` also validates exported grids, strips and image references and rejects exports with an older data schema. For a visible browser smoke test, start `pnpm dev` in another terminal, install Chromium once with `pnpm exec playwright install chromium`, then run `node scripts/browser-smoke.mjs`. It checks sidebar collapse, fuzzy search and finding selection, full search/selection/camera URL restoration, deck switching, mobile layout, constant detail near map edges, background motion/pause, cache settling and pixel-level cutaway behavior. A regression check covers Tramstation Z2 tiles X114/Y63 (porous asteroid rock) and X114/Y62 (open space). Screenshots and a JSON report are saved under `.cache/qa/`. Set `ATLAS_URL` to test a production preview at a repository subpath.

`node scripts/features-smoke.mjs` checks the 16-map picker, resize grip, simple/detailed inspector, door roles, option-mask restoration and current-deck direction arrows. `node scripts/utility-smoke.mjs` compares utility-toggle pixels and verifies that the first zoom out needs no new image requests. `node scripts/terrain-smoke.mjs` checks natural terrain replacement, the original-marker toggle and door access and exclusion lists. `node scripts/cache-smoke.mjs` saves the full dataset in a fresh visible browser profile, restarts the browser, blocks map/sprite network requests and verifies previously unselected maps can still open. The full cold-cache check exercises roughly 452 MiB of resources; its profile and JSON evidence remain under `.cache/qa/` for review or reuse.
